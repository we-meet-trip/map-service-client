# 릴리스 운영

실기기에 앱을 올리고, 그 뒤로 판을 계속 내보내는 절차다.

## 전체 그림

```
맥 로컬 스택 ──(관문 8090)── 터널 ──▶ https://<임의>.trycloudflare.com
                                              │
                       app_config.json 에 게시 │
                                              ▼
   태그 푸시 ──▶ CI(서명·검증) ──▶ 테스터 배포 ──▶ 폰의 앱 ──(시작 시 주소 조회)
```

**설치본에는 서버 주소가 들어 있지 않다.** 앱은 시작할 때
`https://mapcenter-b59ca.web.app/app_config.json` 에서 현재 주소를 읽는다.
서버가 옮겨 다녀도 그 파일만 갈아 끼우면 되고, 앱을 다시 만들거나 깔지 않는다.

주소를 정하는 순서는 `lib/core/config/app_config.dart` 에 있다:
빌드 주입값 > 원격 > 마지막 성공값 > 로컬 기본값.
개발 중 `--dart-define=API_BASE_URL=...` 을 주면 원격을 아예 보지 않는다.

## 1. 서버 열기 (매 세션)

```bash
cd map-service-client && flutter build web --release
cd ../map-service-infra && ./scripts/map-serve.sh
```

스택 기동 → 관문 확인 → 터널 개통 → 주소 게시까지 한 번에 한다. 게시된 값을
실제로 다시 읽어 확인한 뒤에야 성공으로 본다. 닫을 때는 `map-serve-down.sh`.

터널 주소는 열 때마다 달라진다. 바뀌면 이 명령을 다시 돌리고, 폰에서는 앱을
**다시 시작**하기만 하면 된다(재설치 불필요). 앱은 시작 시 조회에 실패해도
간격을 늘려 가며 몇 번 더 물어보므로, 서버를 나중에 열어도 스스로 붙는다.

호스팅 배포는 `build/web` 디렉터리 내용으로 사이트를 통째로 바꾼다. 그래서
주소 파일이 없는 상태로 배포하면 폰이 읽을 곳이 사라진다. `firebase deploy` 를
따로 돌리면 배포 전 검사에서 막히니, 배포는 위 스크립트로만 한다.

알려진 한계: 터널은 원본 응답을 120초까지만 기다린다. 일정 생성은 통상 그
안에 끝나지만, 넘어가면 앱에는 실패로 보인다.

## 2. 판 내보내기

```bash
git tag v1.0.1 && git push origin v1.0.1
```

`.github/workflows/release.yml` 이 받아서 한다:

1. 실행 설정(`.env`)과 서명 키를 시크릿에서 되살린다
2. 판 이름은 태그에서, 판 번호는 실행 회차에서 가져온다
3. 설치본을 만든다 — **서버 주소는 주입하지 않는다**
4. **서명 지문을 대조한다.** 배포용 키가 아니면 여기서 멈춘다
5. 저장소 릴리스에 붙이고, 테스터 그룹으로 보낸다

4번이 핵심이다. 키가 없으면 gradle 은 개발용 키로 조용히 서명하고 빌드를
성공시킨다. 그 설치본은 기존 설치를 덮어쓰지 못하고 초대 링크 검증도 통과하지
못하는데, 겉으로는 정상 산출물과 구분되지 않는다.

손으로 돌릴 때는 Actions 에서 `release` 를 실행한다. `build_ios` 를 켜면 iOS
빌드 건전성까지 확인하는데, 맥 러너는 같은 시간에 열 배로 과금된다.

### 필요한 시크릿

| 이름 | 내용 |
|---|---|
| `APP_DOTENV_B64` | 실행 설정 파일을 base64 로 인코딩한 값 |
| `ANDROID_KEYSTORE_B64` | 배포용 키스토어를 base64 로 인코딩한 값 |
| `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_PASSWORD` / `ANDROID_KEY_ALIAS` | 키스토어 자격 |
| `FIREBASE_ANDROID_APP_ID` | 배포 채널의 앱 식별자 |
| `FIREBASE_SERVICE_ACCOUNT_B64` | 배포 권한을 가진 서비스 계정 키(JSON)를 base64 로 인코딩한 값 |

## 3. 폰에 설치

테스터로 등록된 계정에 배포 알림 메일이 온다. 링크를 열고 안내에 따라 설치
프로필을 한 번 받은 뒤부터는 새 판이 나올 때마다 알림으로 받는다.

첫 설치 뒤 확인할 것:

- 서버가 열려 있어야 로그인부터 동작한다(1번 절차 선행)
- 지도 타일이 뜨는지 — 뜨지 않으면 지도 콘솔의 앱 등록 문제다
- 초대 링크를 눌렀을 때 앱이 뜨는지 — `docs/deep_link_setup.md`

## iOS 실기기

애플 개발자 계정이 정해진 뒤의 일이다. 빌드 준비(번들 식별자·권한 문구·앱
전용 주소·Podfile)는 되어 있고, 남은 것은 서명이다.

**무료 계정** — 7일마다 만료되고 기기를 개발자 모드로 두어야 한다.

1. Xcode 로 `ios/Runner.xcworkspace` 를 연다
2. Runner 대상의 Signing & Capabilities 에서 개인 팀을 고른다
3. 케이블로 연결한 기기를 골라 실행한다

**유료 계정** — 만료 없이 여러 기기에 배포할 수 있다.

1. 개발자 계정에서 앱 식별자 `kr.mapservice.client` 를 만든다
2. Xcode 에서 팀을 지정하고 Archive → App Store Connect 업로드
3. TestFlight 로 테스터를 초대한다

로컬 맥에는 현재 Xcode 본체가 없다(명령줄 도구만 있음). 빌드가 서는지는
`release` 워크플로를 손으로 돌려 `build_ios` 를 켜면 맥 러너에서 확인된다.
