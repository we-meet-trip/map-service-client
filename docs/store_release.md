# 스토어 배포 — 지금 가능한가, 무엇이 남았는가

이 문서는 앱을 Google Play·원스토어·App Store 에 올릴 수 있는 상태인지 실제로
확인한 결과와, 각 스토어에 올리는 방법을 적는다. 확인은 저장소의 파일과
키스토어를 직접 읽어서 했고, 확인하지 못한 것은 그렇게 적었다.

## 1. 한 줄 판정

| 스토어 | 지금 올릴 수 있는가 | 남은 것 |
|---|---|---|
| Google Play | 아니다 | 회원 탈퇴, 개인정보처리방침, 런처 아이콘, 고정 서버 주소 |
| 원스토어 | 아니다 | 위와 같음 (묶음 파일은 필요 없어 낱개로도 된다) |
| 위치정보법 신고 | **완료** | 시스템을 옮기면 변경신고를 확인한다 |
| App Store | 아니다 | 위에 더해 애플 개발자 계정과 서명 |

빌드 자체는 된다. 막고 있는 것은 대부분 정책과 준비물이지 코드가 아니다.

## 2. 확인한 것 — 이미 갖춰진 것

| 항목 | 값 | 근거 |
|---|---|---|
| 꾸러미 이름 | `kr.mapservice.client` | `android/app/build.gradle.kts` |
| 최소·목표 SDK | 24 / 36 | 같은 파일. Play 의 목표 SDK 요구를 넘는다 |
| 배포 서명 | 실제 키로 서명되고, 워크플로가 지문을 대조해 다르면 빌드를 멈춘다 | `.github/workflows/release.yml` |
| 묶음(aab)·낱개(apk) | 둘 다 만든다 | 같은 파일 |
| 판번호 | 커밋 수에서 뽑는다(되감기지 않는다) | 같은 파일 |
| 백그라운드 위치 | 쓰지 않는다 | 매니페스트에 `ACCESS_BACKGROUND_LOCATION` 없음 |
| 광고·추적 도구 | 없다 | `pubspec.yaml` |
| 평문 통신 | 배포본에서 닫혀 있다 | 본 매니페스트에서 제거, 개발용에만 남김 |
| 앱 링크 검증 | 꾸러미 이름과 지문이 실제 값과 맞다 | `hosting/.well-known/assetlinks.json` |
| 커밋된 비밀 | 없다 | 이력 전체 확인 |

백그라운드 위치와 광고 도구가 없다는 것은 실무에서 크다 — Play 의 별도 신고
양식과 애플의 추적 동의 화면이 통째로 필요 없어진다.

## 3. 남은 것 — 무엇을, 왜, 어떻게

### 3.1 회원 탈퇴가 동작하지 않는다 (막힘 · Play·App Store 정책)

`lib/features/mypage/screens/profile_edit_screen.dart` 의 탈퇴 확인 버튼은
다이얼로그만 닫는다. 화면은 "모든 정보가 삭제됩니다" 라고 알리는데 아무 일도
일어나지 않는다. 서버에도 탈퇴 경로가 없다(`map-service-user` 의 DELETE 매핑
전수 확인).

계정을 만들 수 있는 앱은 **앱 안에서 계정을 지울 수 있어야** 하고, Play 는
**웹에서도 지울 수 있는 주소**를 함께 요구한다.

해야 할 일:
1. 서버에 `DELETE /api/v1/users/me` 를 만든다. 지울 때 함께 정리할 것 —
   일정, 대화 참가, 갱신 토큰, 소셜 연결. 대화방은 방장이 나가면 어떻게 할지
   정해야 한다(즉시 폐쇄 / 다른 참가자에게 넘김).
2. 앱의 확인 버튼을 그 경로에 잇고, 성공하면 로그아웃 후 첫 화면으로 보낸다.
3. 웹 삭제 요청 페이지를 호스팅에 올린다.

### 3.2 개인정보처리방침·약관·동의가 없다 (막힘 · 세 스토어 모두)

앱과 호스팅 어디에도 없다. 가입 흐름에도 동의 절차가 없다.

이 앱은 위치·카메라·음성·프로필을 받는다. 스토어 등재에 방침 주소가 필수이고,
국내법상으로는 수집 전 동의가 별도로 필요하다. 위치는 특히
**위치정보법**이 별도로 규율한다 — 아래 3.6 을 함께 본다.

해야 할 일: 방침·약관 문서를 만들어 호스팅에 올리고, 가입 흐름에 동의 단계를
넣고, 마이페이지에서 다시 볼 수 있게 한다. 문서 내용은 서비스 운영 주체가
정할 사항이라 코드로 대신할 수 없다.

### 3.3 런처 아이콘이 Flutter 기본 아이콘이다 (막힘 · 등재 품질)

`android/app/src/main/res/mipmap-*/ic_launcher.png` 다섯 개가 Flutter 템플릿
파일과 바이트 단위로 같다. 적응형 아이콘도 없다. iOS 아이콘은 갖춰져 있다.

원본 그림은 저장소 위에 있으나(`모바일 아이콘.png`, 402×546) 정사각형이
아니다. 정사각 캔버스에 어떤 배경과 여백으로 앉힐지는 디자인 결정이라
여기서 정하지 않았다. 정하고 나면 `flutter_launcher_icons` 로 한 번에 만든다.

### 3.4 설치본이 가리킬 고정 서버 주소가 없다 (막힘)

앱은 서버 주소를 게시된 설정 파일에서 받는다. 지금 그 파일에 적혀 있는 것은
실행할 때마다 달라지는 임시 터널 주소다. 스토어에서 받은 사람은 그 주소가
살아 있을 때만 앱을 쓸 수 있다.

해야 할 일: 운영 서버를 고정 주소로 올리고(배포 문서 참고) 그 주소를 설정
파일에 적는다. **앱을 다시 빌드할 필요는 없다** — 설정 파일만 바꾸면 된다.
아울러 마지막 수단 주소가 `http://localhost:8080` 이라, 설정 파일을 못 읽으면
아무 데도 닿지 못한다. 운영 주소로 바꾸는 것이 좋다.

### 3.5 iOS 는 서명할 수 없다 (막힘 · App Store 만)

`ios/Runner.xcodeproj/project.pbxproj` 에 개발팀 값이 없다. 프로비저닝 파일도
없다. 유료 애플 개발자 계정이 정해지기 전에는 아카이브 자체가 되지 않는다.
배포 대상 최소 버전은 iOS 13.0 이다.

수출 규정 질문은 미리 답해 두었다(`ITSAppUsesNonExemptEncryption=false`).
이 앱이 쓰는 암호는 운영체제가 주는 https 뿐이고, 저장 본문을 감싸는 일은
서버에서 한다.

### 3.6 위치기반서비스사업 신고 — 완료

신고를 마쳤다. 남는 것은 신고한 내용과 실제 구현을 계속 맞추는 일이다.

- 신고 서류의 **위치정보 보호조치**는 저장 본문 암호화와 접근 로그에서 좌표를
  뺀 것으로 채워진다.
- **위치정보시스템이 바뀌면 변경신고 대상이다.** 서버를 클라우드로 옮기는 것이
  여기에 해당할 수 있으니, 옮긴 뒤에 확인한다.
- 수집·이용·제공 사실을 자동으로 기록해 두어야 하며, 그 기록에는 **좌표를
  넣지 않는다.** 누가 언제 무엇을 했는지만 남긴다.
- 목적을 다한 개인위치정보는 지체 없이 파기해야 한다. 지금은 기기가 잰 좌표를
  요청 처리에만 쓰고 저장하지 않으므로 이 조건을 이미 만족한다 — 저장하도록
  바꾸는 순간 파기 절차가 함께 필요해진다.

## 4. 올리는 방법

### 4.1 공통 — 산출물 만들기

태그를 밀면 워크플로가 낱개(apk)와 묶음(aab)을 함께 만들고, 배포 키로
서명됐는지 지문을 대조한 뒤 산출물로 올린다.

```
git tag v1.0.0 && git push origin v1.0.0
```

필요한 저장소 비밀값은 `docs/release.md` 의 표에 있다.

### 4.2 Google Play

1. Play Console 에서 앱을 만든다. 꾸러미 이름은 `kr.mapservice.client` 이며
   **한 번 정하면 바꿀 수 없다.**
2. **Play 앱 서명**을 켠다. 켜면 구글이 배포용 키를 새로 만들고, 우리가 가진
   키는 업로드 전용이 된다. **그 순간 `assetlinks.json` 의 지문이 달라진다** —
   콘솔의 앱 서명 지문으로 바꿔 올리지 않으면 초대 링크가 앱을 열지 못한다.
3. 묶음(aab)을 올린다. 낱개(apk)는 새 앱에 받지 않는다.
4. 데이터 안전 양식을 채운다. 위치·카메라·마이크·프로필을 수집한다고
   적고, 전송 구간 암호화와 삭제 요청 경로를 함께 적는다.
5. 개인정보처리방침 주소를 넣는다(3.2).
6. 내부 테스트 → 비공개 테스트 → 프로덕션 순으로 올린다.

### 4.3 원스토어

1. 원스토어 개발자 센터에 앱을 만든다. 꾸러미 이름은 Play 와 같아도 된다.
2. **낱개(apk)를 그대로 올린다.** 묶음도 받지만 낱개로 충분하다.
   Play 앱 서명 같은 재서명이 없어 `assetlinks.json` 지문이 그대로 유효하다.
3. 등급 분류와 개인정보처리방침 주소가 필요하다.
4. 국내 스토어라 심사 안내를 한국어로 쓸 수 있다. 시험 계정을 함께 적어
   준다(`TESTER_ACCOUNTS.md`).

### 4.4 App Store

1. 유료 개발자 계정을 만든다(연 129,000원).
2. Xcode 본체를 설치한다. 지금 이 컴퓨터에는 명령줄 도구만 있다.
3. `ios/Runner.xcodeproj` 에 팀을 지정하고 번들 식별자를 등록한다.
4. `flutter build ipa` 로 만들어 TestFlight 에 올린다.
5. 심사에는 위치·카메라·마이크를 왜 쓰는지 적고, 시험 계정을 함께 준다.

## 5. 순서 제안

1. 고정 서버 주소 (3.4) — 이것이 없으면 나머지를 해도 앱이 동작하지 않는다.
2. 회원 탈퇴 (3.1) — 서버와 앱 양쪽이라 가장 오래 걸린다.
3. 개인정보처리방침·약관·동의 (3.2) 와 신고 (3.6) — 함께 준비하면 겹치는
   내용이 많다.
4. 런처 아이콘 (3.3).
5. 원스토어 먼저 올린다 — 묶음도 재서명도 없어 걸리는 것이 가장 적다.
6. Play, 그다음 App Store.
